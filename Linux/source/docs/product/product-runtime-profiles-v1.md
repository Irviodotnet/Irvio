# HYDRA Alpha product runtime profiles v1

The Linux desktop daemon still accepts the zero-argument command `hydrad`. In the packaged on-demand deployment, `irvio.socket` listens on `/run/irvio/control.sock`; opening the UI activates `irviod.service` without giving the UI service-management privileges. The daemon starts idle without changing ordinary WAN routing. The user imports an existing `irvio-bootstrap:v1:` code through the UI, selects a country, then chooses Connect. Connect starts a production CLIENT+EXIT runtime. Explicit Disconnect tears down that runtime, including its own tunnel, Exit registrations, downstream leases, DHT participation and ProtectedMode, before returning to idle. The top-right close button and tray **Shutdown Hydra** action request daemon-owned teardown, wait for acknowledgement, then exit the UI; `irviod.service` exits normally while `irvio.socket` remains listening. An unexpected GUI crash does not disconnect an active tunnel.

The same-boot ConnectIntent is an owner-only file in `/run/irvio/session-state`. It contains only the requested country and a versioned desired state, not the old Exit or transport secrets. After a daemon crash, systemd restarts the service, ProtectedMode is adopted before recovery, and the daemon re-enters discovery/ExitSelector for the requested country. Failed recovery remains fail-closed. Disconnect and Shutdown first record teardown intent, then clean up; a crash mid-teardown resumes cleanup rather than reconnecting. A new OS boot clears `/run`, so there is no automatic Connect. The boot-time oneshot reconciles only HYDRA-owned previous-boot residue before opening the Local API socket. An idle daemon with no Local API clients exits after one minute; an active ConnectIntent prevents that idle exit. See [on-demand deployment](on-demand-desktop-lifecycle.md).

The intended public server command is:

```bash
hydrad --role server --bootstrap 'irvio-bootstrap:v1:<bundle>'
```

The server preset requests DHT server, Public Control, Rendezvous, STUN UDP/3478 and Exit capabilities. M11 still requires its existing independent-verifier quorum; the preset selects signed public Rendezvous peers and, when needed, independent direct IPv4 peers from the bootstrap bundle. The existing M11 challenge verifies every selected peer and still requires two attestations. Country Exit publication waits until M11 verification and Rendezvous service activation, in addition to local data-plane and GeoIP readiness. If M11 readiness is lost, the signed country Exit capability and Rendezvous registration are withdrawn; after verification and DHT rejoin, they can resume without a daemon restart. If fewer than two usable independent verifiers exist, public readiness cannot be claimed. Genesis remains an internal deployment mechanism, not a public role.

Every direct public IPv4 bootstrap address contributes an STUN seed at the same IP on UDP/3478. The complete bundle remains available for bootstrap and STUN fallback. Relay, private and non-direct addresses are not promoted to production STUN seeds. Alpha public servers must expose STUN UDP/3478 on the same public IP as their bootstrap multiaddr; host/NAT firewall configuration remains an operator deployment responsibility.

Linux selects underlay interface and source with a kernel route lookup, not an interface-name heuristic. Each profile randomly chooses and persists a locally non-conflicting private Exit /24; assigning every new node the same first free pool would make a dual-role client's tunnel control route to itself when its upstream Exit had that pool. Independent random selection reduces, but cannot mathematically eliminate, collisions between remote nodes without shared allocation. Exit country is resolved from a live public STUN observation by the existing CountryResolver using DB-IP Country Lite at `/var/lib/irvio/geo/country.mmdb`. The MMDB is an installer/package asset, never a Git or Flutter asset; packaging must retain DB-IP attribution. If the database or observed country is unavailable, country is UNKNOWN and the Exit is not advertised as an Exit for a country. A desktop Connect requiring contributor readiness fails instead of silently claiming a client-only connection.

The optional `/etc/irvio/config.json` currently supports only `{"version":1}` and an optional `"role":"desktop"|"server"`. Unknown fields and versions fail startup. Identity, learned peers, public IP, WAN interface, country and current routes belong to profile or runtime state, not this file. Legacy low-level flags remain available in the engineering CLI for existing lab deployments; they are not the normal Alpha command.

This implementation is not an Alpha release claim until privileged product-path lifecycle and server-readiness validation passes. See [validation status](../testing/product-runtime-profiles-v1-validation.md).
