## Install and run

Test target: Windows 11 x64; native build runs on Pro. Home and a second physical
laptop are not established by this build. Administrator approval is required
for installation; the GUI runs as the selected ordinary desktop user.

1. Copy the EXE, `SHA256SUMS` and this document to the laptop. SDKs are unnecessary
   for installation. Compare the file hash with the independently obtained list:

   ```powershell
   Get-FileHash .\irvio-setup-development.exe -Algorithm SHA256
   ```

2. Double-click the EXE from your own desktop account; approve the installation
   confirmation and UAC. Do not launch it as SYSTEM or another desktop user.
3. Open IRVIO from Start, or run:

   ```powershell
   & 'C:\Program Files\IRVIO\ui\irvio.exe'
   ```

4. Import a trusted bootstrap link/QR, choose a country and press CONNECT. Opening
   the UI alone does not request a VPN connection. This package includes no
   bootstrap, invitation, user identity or profile.
5. Use DISCONNECT for ordinary disconnection and Shutdown IRVIO for full exit.
   Force-killing the daemon is not a normal shutdown: protection intentionally
   remains until automatic recovery or explicit safe teardown.

IRVIO's EXE is development-unsigned. Official dependency signatures are checked
when packaging, but they do not sign IRVIO itself. Do not disable Defender,
Secure Boot or driver signature enforcement. If device policy refuses the
package, retain the error and stop the test.

## Diagnostics and removal

```powershell
Get-Service IRVIO,IRVIO-Recovery
Get-ChildItem 'C:\ProgramData\IRVIO\logs\daemon-*.jsonl'
.\irvio-setup-development.exe --uninstall
```

Close the GUI normally before uninstalling. The uninstaller offers profile
preservation or deletion; deleting the profile removes the local identity and
saved Private VPN access. Do not manually remove protective filters, drivers or
ProgramData to bypass an error. Logs can contain PeerIDs and addresses; inspect
before sharing them.

## Build from the supplied source archive

Run these commands in Windows PowerShell. The lab toolchain is Go 1.27.1,
Flutter 3.47.4 / Dart 3.13.3, Visual Studio C++ desktop tools with Windows SDK and
CMake. Add Go, Flutter and Git to PATH. Dependency caches are not included;
first-time Go/Dart dependency resolution may need network access. Each command
must succeed before proceeding.

```powershell
New-Item -ItemType Directory source
tar.exe -xf .\irvio-source-dfda729.tar -C .\source
Expand-Archive .\irvio-windows-payload-dfda729.zip -DestinationPath .\reference-payload
$base = (Get-Location).Path
Set-Location .\source
New-Item -ItemType Directory out
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go build -trimpath -o .\out\irviod.exe ./cmd/irviod
go vet ./...
Set-Location .\ui
flutter pub get --enforce-lockfile
flutter analyze --no-pub
flutter test --no-pub
flutter build windows --release --no-pub
Set-Location ..
```

The GUI's CMake build also builds `irvio-ui-bridge.exe` from the same source tree.
Do not copy only the GUI EXE: it requires the entire Release directory, DLLs and
data. A standalone daemon EXE does not replace installation of SCM services,
protected ACLs, drivers and GeoIP.

## Build the standalone development installer

Use the supplied payload only as the verified source of unchanged third-party
dependencies, MMDB and licenses. New daemon and GUI must come from the new build.
The dependency manifests have not changed from the preceding package. When
changing dependencies yourself, regenerate their license inventory too.

```powershell
$ui = Join-Path $PWD 'ui\build\windows\x64\runner\Release'
$deps = Join-Path $base 'reference-payload'
foreach ($name in @('msvcp140.dll','vcruntime140.dll','vcruntime140_1.dll')) {
    Copy-Item (Join-Path $deps "ui\$name") (Join-Path $ui $name)
}
# Remove only debug symbols generated by this build, not installed files.
Get-ChildItem $ui -File -Filter '*.pdb' | Remove-Item
.\packaging\windows\stage-payload.ps1 `
  -Daemon "$PWD\out\irviod.exe" -UIBundle $ui `
  -Wintun "$deps\daemon\wintun.dll" -WinDivertDirectory "$deps\driver" `
  -GeoIP "$deps\geo\country.mmdb" -GeoAttribution "$deps\geo\ATTRIBUTION.md" `
  -Licenses "$deps\licenses" `
  -SourceRevision 'dfda72923e68741dd600cfdae4ce166e2b5ae186' `
  -Version '1.1.0-windows-test.dfda729' `
  -Output "$base\new-payload" -DevelopmentUnsigned
$manifest = (Get-FileHash "$base\new-payload\payload-manifest.json").Hash
.\packaging\windows\build-setup.ps1 `
  -Payload "$base\new-payload" -ManifestSHA256 $manifest `
  -Go (Get-Command go.exe).Source `
  -Windres 'C:\Tools\llvm-mingw-20261006-ucrt-x86_64\bin\x86_64-w64-mingw32-windres.exe' `
  -Output "$base\new-setup" -DevelopmentUnsigned
```

Replace the windres path with your actual toolchain location. Output directories
must not exist. The packaging script verifies the embedded payload without
installing it. If you edit the source, use its real new revision/version rather
than labeling it dfda729. Identical hashes across independent rebuilds are not
promised. These instructions are an external companion to the frozen archive;
they do not change that archive's source revision.

## Native regression fixture

On Windows, use the existing disposable-VM harness for whole-tree tests:

```powershell
$env:CGO_ENABLED = '1'
$env:CC = 'C:\Tools\llvm-mingw-20261006-ucrt-x86_64\bin\x86_64-w64-mingw32-clang.exe'
.\tools\windows\w12\integration-check.ps1 -DisposableVM -Scope Full `
  -Evidence C:\IRVIO-Lab\new-full-regression
```

Run elevated inside the disposable VM, with no concurrent network experiments.
It adds/removes two owned loopback aliases needed by the source-migration tests
and checks exact cleanup. Running bare `go test ./...` without those aliases
fails two migration cases on Windows; do not bypass source ownership or replace
their test addresses to obtain PASS. Full shuffled/race results for this build
must be checked separately from its build-verdict; compilation and package hash
validation alone are not a full regression or installed-runtime acceptance.
